## Project Overview

Model Builder V3 is a quantitative trading research platform combining a Streamlit web interface with CLI tools for portfolio curation, strategy optimization, and simulation review. The project uses evolutionary algorithms to tune trading strategy parameters (primarily ATR breakout strategies) against historical market data, with backtesting and risk assessment capabilities.

## Architecture

### Module Organization

- **src/config/**: Environment-based configuration (`AppSettings` reads from env vars or Streamlit secrets)
- **src/storage/**: File system layout for artifacts (`StorageLayout` manages paths for portfolios, parameters, logs, simulations)
- **src/data/**: Market data providers (Alpaca via `alpaca_client.py`, Yahoo Finance via `yahoo_client.py`) with caching and universe loading
- **src/portfolio/**: Portfolio creation workflows (filtering, liquidity checks, ticker validation)
- **src/engine/**: Core trading logic (`atr_breakout.py` implements ATR breakout signals, `backtest.py` runs vectorized backtests with cost modeling)
- **src/optimizer/**: Evolutionary optimization (`evolutionary.py` contains the genetic algorithm, `telemetry.py` logs runs)
- **src/model_builder/**: Strategy profile management (profiles define parameter search spaces and train/holdout splits)
- **src/cli/**: Typer-based CLI interface
- **src/home/**: Dashboard summary aggregation
- **pages/**: Streamlit multi-page components (Portfolio Curator, Model Builder, Log Inspector, Simulation Review)

### Key Data Flows

1. **Portfolio Curation**: User defines filters → tickers validated → liquidity checked → portfolio saved as JSON in `storage/portfolios/`
2. **Strategy Optimization**: User selects portfolio + strategy profile → optimizer generates parameter candidates → each candidate backtested on training window → best parameters saved to `storage/parameters/` with JSONL telemetry in `storage/logs/`
3. **Simulation Review**: Parameter set loaded → backtest re-run on holdout window → equity curves and trade records visualized
4. **Market Data**: Data providers fetch OHLCV bars → cached as Parquet shards in `storage/ohlcv/{symbol}/{interval}/`

### Storage Layout

The `StorageLayout` class (src/storage/layout.py) enforces a canonical directory structure under `DATA_DIR` (defaults to `storage/`, overridable via environment variable):

```
storage/
├── portfolios/        # Portfolio definitions (JSON)
├── parameters/        # Tuned parameter sets (JSON)
├── logs/              # Optimizer telemetry (JSONL)
├── simulations/       # Simulation artifacts
├── strategy_profiles/ # Strategy profile definitions (JSON)
├── evaluations/       # Evaluation run logs and artifacts
├── ohlcv/             # Market data cache (Parquet shards by symbol/interval)
└── benchmarks/        # Benchmark series (Parquet)
```

### Evolutionary Optimizer

The `EvolutionaryOptimizer` (src/optimizer/evolutionary.py) implements a constraint-aware genetic algorithm:

- **Objective**: Weighted combination of CAGR, Sharpe, Calmar (configured via `ObjectiveWeights`)
- **Constraints**: Hard gates on `max_trade_rate` and `min_hold_days` (violations penalize fitness via `ConstraintGate`)
- **Selection**: Top 1/3 elite retained, remainder generated by mutation
- **Parallelization**: Supports multi-process evaluation via `max_workers` parameter
- **Telemetry**: Every candidate logged via `TelemetryPublisher` to JSONL

### Backtest Engine

The `run_backtest` function (src/engine/backtest.py) executes vectorized portfolio simulations:

- Accepts prices (DataFrame), signals (DataFrame with timestamp/symbol/weight), initial capital
- Rebalances portfolio daily to match target weights
- Applies transaction costs via `CostModel` (commission, slippage, borrow costs)
- Returns `BacktestResult` with equity curve, trade records, KPIs (CAGR, Sharpe, Calmar, max drawdown, turnover, hit rate)
- Risk notes auto-generated for drawdowns >20% or turnover >4.0

### ATR Breakout Strategy

The `atr_breakout_signals` function (src/engine/atr_breakout.py) generates buy signals when close price exceeds rolling high + (ATR × multiplier):

- **Config**: `ATRBreakoutConfig` specifies `atr_window`, `breakout_lookback`, `breakout_multiplier`
- **Risk Sizing**: `RiskSettings` enables dynamic position sizing based on `risk_fraction / (ATR × multiplier)`, clamped to `[min_weight, max_weight]`
- Outputs DataFrame with timestamp, symbol, action, weight, metadata

### Strategy Profiles

`StrategyProfile` (src/model_builder/profiles/models.py) defines a parameter search space for evolutionary optimization:

- Links to a portfolio via `portfolio_id`
- Specifies `train_percentage` to split coverage window into train/holdout
- `atr_warmup_days` controls the warmup period for ATR calculation
- `parameters` dict holds strategy-specific bounds (e.g., `{"atr_window": {"min": 10, "max": 50}}`)

### Configuration

Credentials and settings loaded via `AppSettings.from_env()` (src/config/settings.py):

- `DATA_DIR`: Storage root (default: `storage/`)
- `PREFERRED_PROVIDER`: Data source (`alpaca` or `yahoo`)
- Alpaca credentials: `ALPACA_KEY_ID`, `ALPACA_SECRET_KEY`, `ALPACA_API_BASE_URL`, `APCA_DATA_API_BASE_URL`
- Also checks Streamlit secrets (`st.secrets`) as fallback

## Code Style Conventions

- **Formatting**: Black with 100-char line length
- **Linting**: Ruff with rules E, F, W, I, B, UP, N, S, Q
- **Type Hints**: Required on public APIs (functions, classes)
- **Imports**: Absolute imports from `src/` (configured in pyproject.toml `pythonpath`)
- **Naming**: `snake_case` for functions/variables, `PascalCase` for classes, `ALL_CAPS` for constants
- **Dataclasses**: Frozen where possible (`@dataclass(frozen=True)`) for immutability

## Testing Practices

- Mark slow tests with `@pytest.mark.slow` (not currently configured, but mentioned in AGENTS.md)

## Important Patterns

### Error Handling

- Domain errors (validation) raise `ValueError` with descriptive messages
- File I/O errors bubble up naturally (no catch-all handlers)
- Backtest engine validates input DataFrames early with `KeyError` for missing columns

### Immutability

- Contracts (`Portfolio`, `ParameterSet`, `BacktestResult`) are dataclasses with minimal mutability
- Config objects (`ATRBreakoutConfig`, `RiskSettings`, `ObjectiveWeights`) frozen with `__post_init__` validation
- Use `replace()` or `with_*` methods for updates (e.g., `CoverageWindow.with_warmup_start()`)

### Serialization

- JSON for human-readable artifacts (portfolios, parameters, profiles)
- JSONL for append-only logs (optimizer telemetry, evaluation runs)
- Parquet for time-series data (OHLCV shards, benchmarks)

### Async/Concurrency

- Optimizer supports parallel evaluation via `ProcessPoolExecutor` (controlled by `max_workers`)
- No asyncio usage (synchronous throughout)

## Project-Specific Gotchas

- **Column Naming**: OHLCV DataFrames use lowercase keys (`"high"`, `"low"`, `"close"`) with optional MultiIndex for multiple symbols
- **Warmup Periods**: Strategies require warmup bars (e.g., ATR calculation needs `atr_window` bars). Backtest signals should start after warmup.
- **Signal Format**: Backtest expects signals as DataFrame with `["timestamp", "symbol", "weight"]` columns (pivoted and forward-filled internally)
- **Date Handling**: Portfolios store `coverage_window` with ISO strings; profiles use `date` and `datetime` objects with validation
- **Telemetry Schema**: Optimizer logs are JSONL with event types (`session_start`, `generation_summary`, `checkpoint`, `session_end`)
- **Storage Initialization**: `StorageLayout` methods create parent directories on demand (no manual `mkdir` needed)

## Repository Guidelines (from AGENTS.md)

- Keep production code in `src/`, tests in `tests/`, specs in `specs/`
- Add new features as subpackages (e.g., `src/model_builder/pipelines/`) rather than root-level scripts
- Target 85% statement coverage on new code
- Commit messages: Title-Case, imperative mood (e.g., "Add Pipeline Registry")
- Load secrets from environment (never commit `.env` or credentials)
- Park exploratory notebooks in `notebooks/` with dated prefixes, graduate stable logic to `src/` quickly
